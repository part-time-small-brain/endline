# Security

Every rule here comes from a real loss. Contract changes must keep all of them. The short form is in `AGENTS.md`.

## Threat model

| Threat | Mitigation | Where |
|---|---|---|
| Fake deposit notifications | `mt_on_transfer` only accepts `intents.near` as predecessor. Amounts and sender come from intents, never from `msg` | `receiver.rs` |
| Forced failure of a promise returned from a receiver (Intents $3.8M, Oct 2026) | Receivers return plain values. Delivery and payouts are detached promises with their own callbacks. Our own `*_transfer_call` into `intents.near` carries only a plain deposit `msg` (empty or an account id), so a future intents action that returns a promise can't make our resolve refund tokens intents already credited | `receiver.rs`, `payout.rs`, `mt.rs` |
| Refund callback that over-refunds or panics | Refunds capped by amount sent and by current balance. Results read with `promise_result_checked` and a size cap. Into `intents.near`, only an explicit failure refunds: intents credits a deposit before it answers, so an answer we can't read refunds nothing | `mt.rs`, `payout.rs` |
| Payout above collateral (Ribbon 2025, Vault4626) | Per-series `collateral_locked`, checked before every payout. Payouts stop at the series' `width`, the collateral per contract. Math proven `long + short ≤ refund ≤ collateral` | `close.rs`, `math.rs` |
| Wrong denomination (Ribbon decimals, Injective raw ints) | One collateral asset for every series: the quote asset set at deploy. Each series stores its option decimals at creation. Writes take only the quote asset, closing pays only in it | `write.rs`, `close.rs`, `series.rs` |
| Spot or pool price used for settlement (Rhea, Nostra, Lyra v1, Premia v2) | Price keyed by exact `(underlying, expiry)`, the median of 7 exchanges' TWAPs over the 30 min before expiry, never "latest" | `settlement.rs`, `oracle.md` |
| Wrong oracle price (Paradex BTC=$0, TEE not enforced on-chain) | Price > 0, one hour dispute window, owner override inside it. Median of 7 exchanges (at least 3 required) in the WASM; no price if Deribit's delivery price differs by more than 50 bps or is missing at an 08:00 expiry; the USDT/USD rate needs both sources within 20 bps | `settlement.rs`, `oracle.md` |
| Forged or stale OutLayer result | WASM pinned by sha256. `#[private]` callback with a capped read that checks `ok`, index, expiry, price > 0 and no existing proposal; failure stores nothing; a stale callback can't release a newer request's lock. Requests only for listed expiries inside the oracle window. WASM-side checks: [oracle.md](oracle.md#what-the-wasm-computes) | `oracle.rs`, `oracle/` |
| Missing price triggers a refund formula (Injective) | No price means pending. No fallback payout formula. `burn_pair` always works | `close.rs` |
| Series bound to an arbitrary oracle (Injective disabled oracle) | Only whitelisted underlyings. Ids derived from typed fields, exact-match lookup | `admin.rs`, `series.rs` |
| Settlement-window games (Polymarket 5-min markets) | Writes and quotes stop at `expiry − write_cutoff_sec` (mainnet 30 min, the TWAP start). Price is a 30 min TWAP | `write.rs`, `rfq.md` |
| Double exercise (Opyn v1, Hegic) | Ledger closes burn before paying. Intents closes move tokens into our intents account, which nothing can move out | `close.rs` |
| Rounding dust farming | Collateral rounds up, payouts round down, minimum write per underlying | `math.rs`, `write.rs` |
| Overflow | U256 intermediates, panic over u128, `overflow-checks = true` in release | `math.rs`, `Cargo.toml` |
| Storage drain via series or balance-row spam | `create_series` and ledger transfers charge the caller for new storage. `create_series` also creates, empty, the rows its first write fills, so the creator pays for them and create → write loops don't drain the contract | `admin.rs`, `mt.rs` |
| Admin abuse / key loss | Owner can pause writes and override a price inside the window only; the override keeps `final_at`. New oracles and oracle WASMs take effect only `oracle_delay_sec` after the call (1 day on mainnet). Ownership moves only when the new owner accepts, so it can sit behind a multisig. The dispute window is fixed at deploy (60 s to 1 day), so the owner can't shorten it and make a price final instantly. No method moves collateral out of a series, but the override price decides how it splits between longs and shorts. Exits never pausable. Not covered: the owner can stall settlement (known gaps) | `admin.rs`, `oracle.rs`, `settlement.rs` |
| Callback misreads a successful call as failed | Refunds and claimables only on an explicit `PromiseError::Failed`, never on unreadable results | `payout.rs` |
| Function-call keys draining value | 1 yocto on every value-moving or admin method | everywhere |
| Unbounded loops | Batches capped at 10 tokens (intents and ledger). Resolve gas scales with batch size. No iteration over holders. Views paginated (≤ 200) | `receiver.rs`, `mt.rs`, `views.rs` |
| Log overflow in callbacks (16 KB limit, part of the Intents exploit) | Small batches, short ids, one event per action | `events.rs` |
| Relay as a free 1Click partner key | `/deposit-quote` forwards only a deposit into an intents balance in `QUOTE_ASSET` (strict schema: no `appFees`, `rebates`, `referral`, deadline within 24 h), same-origin with `application/json` required, 30 requests/min per IP and 60/min in total | `apps/relay` |
| Tampered 1Click deposit quote (swapped `depositAddress`) | The relay answers a deposit quote, and the app shows it, only if 1Click's Ed25519 signature verifies against its pinned key (the SDK's `verifyDepositQuote` in both), over the request we sent plus the quote, so a quote signed for another recipient, asset or amount fails too; otherwise `502`. The app reads only signed fields (`depositAddress`, `amountIn`, `amountOut`, `timeEstimate`, `amountInUsd`, `amountOutUsd`), refuses a quote that loses more than 3% between the USD amounts or carries a `depositMemo` it wouldn't show, and shows the amount that arrives | `apps/relay`, `apps/web`, `packages/sdk` |
| Relay as a free gas payer | `/execute` and `/claims` accept only a canonically encoded exercise of our long tokens (exact `exerciseOptions` shape, series in the `/series` listing, at least `min_write`, final price + 60 s, total payout at least $1, so a win split into many tiny exercises costs the relayer at most ~2% of it in gas). Each `(signer, nonce)` sent once per relay process; an errored `/execute` or `/transfer` is settled by its nonce like a trade ([rfq.md](rfq.md) step 5), so a move that ran answers `200` instead of an error that invites a second signature, and a claim is resent only if its nonce is still unused; one payload per signer in flight (exercise or transfer); every payload must still have 2 min left after our simulation, since intents rechecks the deadline on-chain and sending retries for up to ~85 s, and must write its deadline exactly as the SDK does, so padding can't inflate the gas; and `/execute` and `/transfer` payloads must expire within 10 min so the sent-once map stays small. Claims only for options the signer bought through the relay, one per buy, each able to pay at least $1; a signer's claims on a token can't exceed their balance or net relay buys; 1,000 claims in total. `/transfer` takes only one plain `QUOTE_ASSET` transfer (no `msg`, so no contract call) followed by a $0.01 fee to the relayer, more than its ~6 TGas while NEAR is under $10, so moving money through it costs the sender; it shares the sent-once map and the one-in-flight-per-signer rule. 30 requests/min per IP | `apps/relay` |
| Quote spam locking MM inventory | Every quote needs a session signed by its signer (empty intents payload, `simulate_intents`-checked, ≤ 7 days), so nobody quotes in someone else's name. A signer's quotes in auction or settling can't exceed their intents balance (premiums for buys, sizes per option for sells), and issuing a new quote expires their earlier unsigned one, so each signer has at most one open quote. MMs hold their reservation to their own 25 s deadline whatever the relay reports, so a buyer needs $1 (the smallest premium) before any auction and each signer gets 4 quotes per 25 s once funded, a settled trade giving its slot back within the window (a real fill): a few locks per signer (fixed windows and the ~30 s reservation tail allow up to about 12 in a burst). A settled trade's reservation also lasts to its deadline, so a funded signer trading back and forth can lock up to the per-IP limit, paying the spread and relayer gas on every fill. The relay assumes no MM sells for under $1, the `MIN_PREMIUM_USD` default. Unpublished quotes expire at `sign_by_ms`. 30 requests/min per IP (per /64 for IPv6, `TRUST_PROXY` behind a proxy) | `apps/relay`, `apps/mm` |
| Tampered user payload | Relay accepts only the byte-identical payload it issued, once per quote, before expiry | `apps/relay` |
| Swapped NEAR wallet script (mutable selector manifest) | The app ships near-connect's wallet list in `src/wallet/manifest.json`, GitHub-hosted executors pinned to commits. Executors served by a wallet vendor's own site (Intear, NEAR Mobile, Trezu, EVM-on-NEAR) stay as mutable as in any dapp | `apps/web` |
| MIME sniffing, leaky referrers, device access | Caddy sends `nosniff`, a strict referrer policy and no camera, mic, location or payment access. No `frame-ancestors`: wallet apps host dapps in an iframe (near-connect's parent-frame wallets), and a framed page still can't sign without the wallet's own prompt. A full script CSP waits on near-connect, whose sandboxed `srcdoc` wallet iframes inherit the page's CSP | `deploy/Caddyfile` |
| Relay or MM skewing the ticket's prices | The ticket's cost, size, chance and values come from the relay's `GET /marks`, so a lying relay or MM sets what it shows. Funds stay safe: the firm quote comes from the auction and the pre-sign card shows the exact `token_diff` the wallet signs. Before the RFQ opens to outside MMs, the relay must drop marks from an MM whose answer is missing or above its own mark for that series | `apps/relay`, `apps/web` |
| Created series or sent tokens crowding out the MM's marks | The MM marks only series it holds, ranked by what its tokens there are worth at its own bid and ask, and stops before the relay's 64 KB frame. Pushing a series out costs sending the MM tokens worth more than its position there; a series whose price doesn't convert or reaches the width is skipped, never fatal | `apps/mm` |
| Lying relay misleading the pre-sign card | The app takes quote and option decimals from the contract and drops any listed series whose id isn't rebuilt from its terms; the card shows the exact `token_diff` it signs | `apps/web` |
| MM quote that doesn't settle | MM leg must equal the fee-exact expected leg, and `simulate_intents([mm])` must leave exactly the user leg open | `apps/relay` |
| MM double-selling inventory | Reservations taken before signing and held until the signed leg's deadline whatever the relay reports; each cap is checked against the confirmed book plus every pending leg that pushes its way, so it holds whichever legs a compromised relay fills; stale balance reads ignored | `apps/mm` |

## Known gaps (accepted for the hackathon, tracked)

- **Contract NEAR reserve.** Ledger rows created by withdrawals out of intents are paid by the contract. If its NEAR balance falls below its storage requirement, failed payouts can't be recorded as claimable and new settlements can't be stored. Keep a reserve; the [monitor](#monitoring) alerts below 2 NEAR over storage. It watches the intents contract and the relayer (which pays every trade's and the faucet's gas, and on mainnet the settler's requests) the same way.

- **`/deposit-quote` is an open on-ramp under our 1Click key.** It has no session: a bot can quote USDC deposits into any intents account through it. Fees can't be redirected, and the 60/min cap keeps it from burning the key's limits, but that volume counts against our key, and two IPs at the per-IP limit use up the cap and block deposit quotes for everyone for up to a minute.
- **A trade and a transfer from one account can race.** `/publish` has no per-signer lock (only per-quote state and the balance hold), and that hold doesn't count pending transfers, so a quote and a transfer sent at once can both simulate fine and one then fail on-chain on the relayer's gas. Each such failure costs the sender a trade or the $0.01 fee too, and the app never sends both at once.
- **Quote spam is bounded, not gone.** Someone holding premiums worth a series' inventory can keep it reserved without ever trading, since open quotes spend nothing. The balance cap can also be dodged by moving the same funds between accounts within a quote's life (each move is a gas-paid intents transfer, or $0.01 through `/transfer`, which also lets EVM accounts do it).
- **The relayer's key is full-access on testnet and in the mainnet dust test.** It lives in the internet-facing relay. Hosted mainnet needs the split in [mainnet.md](mainnet.md#day-12-trade): a relay key limited to `intents.near` `execute_intents`, the settler on its own account.
- **The contract wasm isn't reproducible.** `mainnet-plan.sh` builds `non-reproducible-wasm` and prints its sha256; nobody else can rebuild it to that hash. `cargo near build reproducible-wasm` needs `[package.metadata.near.reproducible_build]` and a public repository, so it waits until the repo is public.
- **1Click doesn't sign every request field.** `appFees` and `confidentiality` aren't signed, and the captured quote verifies without `depositMode` and `insured` either. A compromised relay could add a fee for itself to a deposit quote. The app refuses quotes that lose more than 3% between the signed USD amounts and shows the signed amount that arrives, so a skim stays under that and in plain sight.
- **The MM counts a fill twice for about 30 s.** It holds every reservation to its leg's deadline whatever the relay reports, so right after a real fill the refreshed balance and the reservation both count it. That only makes the series, delta and vega caps stricter until the reservation lapses (deadline + 3 s + the next 5 s balance read); losing bidders were never told anyway.
- **The relay reads `fills.jsonl` whole** for every `/claims` and `GET /fills/:account`. Fine at hackathon volume; an in-memory index per account is the fix once it grows. `/series` and `/fills` answers aren't capped either.
- **A publish error after broadcast reads as `failed`.** The trade may have landed; the app's balance shows the truth, and the MM no longer frees anything on that word.
- Smaller relay edges, accepted: a replayed session can make one user's open quote expire; MM API keys travel in the `/mm` query string (keep proxy logs private); IPv6 clients are rate-limited per /64; amount strings have no length cap beyond the 64 KB body.
- **The Tap key controls its whole account.** An intents key has no limits, so anyone with the Tap key (script running on our page while the tab is open, or a phished copy of the setup signature, which re-derives it on any site) can move the whole Tap balance anywhere. Never more: the main balance has no Tap key. The seed sits in `sessionStorage` until the tab closes. Wallets whose signatures vary (MPC, some smart wallets) can't set one up, and a NEAR account with a different key on each device gets a different Tap balance on each. Deleting or rotating the key that signed the setup text strands that Tap balance until the key is back, so move it out first.
- **Sessions aren't bound to this app.** A session is an empty intents payload, so one signed for us is accepted by any service using the same scheme, and vice versa.
- **A removed key keeps quoting until the session deadline.** The relay caches verified sessions (≤ 7 days) and doesn't recheck the key. Trades still need a fresh signature checked by intents.
- **Withdraw with `msg`.** If our `mt_batch_transfer_call` panics on an intents `mt_withdraw` with `msg` (e.g. `receiver_id` = intents itself), intents keeps the options burned. Our gas fits the default 50 TGas for 10 tokens (sandbox-tested at 100–200 TGas tx gas), but a user-made panic case still loses their own options.
- Transfers coming from `intents.near` (users withdrawing options out of intents) don't pay storage. Each one costs the attacker a signed intents transaction.
- On testnet, writes and quotes stop 60 s before expiry while the oracle averages the last 30 min, so trades can land inside the averaging window. Mainnet's cutoff equals the window (30 min).
- A failed option delivery lands on the writer's ledger account. Writers today are our MM and lister, which sign NEAR transactions and can deposit them back with `mt_transfer_call`.
- The oracle result's `quote_decimals` and `max_dev_bps` aren't echoed back and checked. The contract builds the input itself and pins the WASM by sha256, so checking them would only tie the contract to a newer oracle build.
- `intents.near` admins can force-withdraw balances, including the option tokens we retire in our own intents account; re-circulated ones would claim what is left of that series' collateral. A trust assumption on intents that our contract can't remove.
- The oracle WASM has only a connect timeout (`wasi-http-client` 0.2 has nothing else). One hanging exchange can run it into its 60 s limit, so the run returns nothing and someone retries.
- **A captured owner key still decides prices.** `override_settlement` sets any price before `final_at`, with no delay, so the oracle delay only stops a slow takeover through a new oracle or WASM. Behind a multisig the override has to pass a vote inside the 1 h dispute window, which weakens the defence against a bad oracle price. Options: [ideas/override.md](ideas/override.md).
- The owner can stall settlement forever: remove every oracle account (`remove_oracle`) and pin a WASM that never returns a price (`set_oracle_wasm`). Markets stay pending and nothing pays out; `burn_pair` still works. On testnet one account is owner, oracle and relayer.
- A whitelisted oracle account or the OutLayer operator can propose any positive price. The only defence is the dispute window plus the [monitor](#monitoring) comparing every proposal with Deribit and the owner overriding in time.
- `create_series` allows any whole-cent strike and width; the creator pays the storage. The MM prices strikes Deribit doesn't list from the interpolated smile. The same strike with another width is another series. The relay marks widths other than the lister's (`listedWidth`) not quotable and refuses to quote them, the MM refuses them too, and the app hides them, so a strike shows once. They can still be written, traded peer to peer and collected.
- The contract is not upgradeable. Fixes ship as a new deployment, and old series stay redeemable.
- **Delete every full-access key on the contract account after deploy.** With a key, someone could call `intents.near` directly as the contract and move all collateral.

## Monitoring

Built: `pnpm --filter @endline/mm start monitor` ([mm README](../apps/mm/README.md#settlement-monitor)), every minute, deduplicated, log + optional webhook, with a `RESOLVED` message when a condition clears (`FINAL` when a flagged price goes final):
- Proposed price more than 20 bps from the Deribit reference (the oracle vetoes at 50), or no reference, while still before `final_at`. Prints the `override_settlement` command with the price left as `<price>`.
- No settlement by expiry + `oracle_window_sec`. Prints the `propose_settlement` command.
- NEAR balance minus storage cost below 2 NEAR, for the options contract, the intents contract and the relayer.
- `HEALTH_URL` (the relay's `/health`) not answering `{"ok":true}` within 5 s, or answering with no market maker connected.
- Each pending oracle and oracle WASM (`get_pending_oracle_changes`, with `active_at`) and a pending owner (`get_config.pending_owner_id`, until `accept_owner`). Admin calls emit no events. An owner proposed and accepted between two checks is never seen.

Not built yet:
- Alert on any single payout above a threshold.
- Solvency check: `Σ collateral_locked` ≤ `intents.near::mt_balance_of(opt, quote_asset)`.
