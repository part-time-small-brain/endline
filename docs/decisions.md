# Decisions

Newest first. One entry per decision: what, why.

## 2026-11-05

- **The product is Endline (wordmark "endline", planned domain endline.trade).** Lite's sentence already reads "BTC ends above": the product is a line and a call on which side of it the price ends, and the name says that without naming the chain. The copy drops "bet" for neutral trading words ("Call where BTC and ETH end"), since these are fully backed options with a known max loss, and the mark (the line with the Up and Down half-discs) stays. Renamed: titles, meta, aria labels, docs, READMEs, the `@endline/*` package scope and the repo. Kept, because something live depends on the old string: the Tap balance text and its `near-options` recipient (the Tap key is the hash of a signature over them, so a change strands funded balances), the testnet account ids, the contract's `near-options` event standard and payout memo, the oracle's User-Agent (the WASM is pinned by hash), the Keychain item the oracle smoke test reads, and the Docker image, compose project and server path names (a separate infra change).
- **Relayed `/transfer` and `/execute` settle an `execute_intents` error by the signer's nonce too, holding the request open until then.** An error answered at once made the Tap sheet show a failure for a move that ran, and the user signed a fresh payload that moved the USDC again. Holding the response (up to the payload deadline, 7 min in the app) keeps the signer's one-in-flight lock, so a second payload gets `409` meanwhile; a ran send answers `200` with `tx_hash` `""`, since no hash is known. Claims keep the resend-if-unused rule: their deadline is days out and a resend reuses the same nonce, so it can't move money twice. If the response is lost (a proxy timeout), the app says it couldn't confirm the move (or collect) and rereads balances instead of saying nothing moved. The cost: a send that definitely failed now answers `500` only once a final block is past its deadline + 5 s (about 7 min for a Tap move), with the signer's lock held all that time, the same trade-off as `/publish`.

## 2026-11-04

- **Every app screen wears the NEAR look; only the landing keeps Horizon** (supersedes "Pro and Positions keep Horizon" below). Switching Lite, Pro and Tap restyled the header, badges, panels and labels each time, and Positions looked like a different product. One look keeps the app single-sourced: Pro's chart reads well on the NEAR palette, where both sides fade from the line as in dark, so the reason to keep Horizon there no longer held. The app has no theme switch; the landing still has one.
- **The hosted backend reads and writes NEAR through dRPC (`https://near-testnet.drpc.org`); the web build keeps FastNEAR.** All five backend services share one server IP. FastNEAR's free tier rate-limited it (19 of 40 calls answered 429) and so does `rpc.testnet.near.org` (429 "this endpoint is deprecated"), which turned `/series` into a 500. dRPC answered 40/40 at ~0.3 s. It once answered `Internal server error` to an `execute_intents` that ran, so it is only safe because the relay settles an errored execute by the user's nonce (next entry) and the lister re-reads balances every cycle. Only the server's `.env` sets it: the web image is built on the Mac from `deploy/env.example`, which stays on FastNEAR because browsers call it from their own IPs.
- **A relay `execute_intents` error settles by the user's nonce, never `failed` at once.** Any RPC can error on a `send_tx` that runs later (nearcore answers `TIMEOUT_ERROR` too), and "nothing was charged" must never be a guess. See [rfq.md](rfq.md) step 5: `failed` is reserved for a failed simulation or a nonce still unused once a final block is past the deadline, judged on chain time, not the relay's clock.
- **The relay serves its last good cached read when a refresh fails.** It logs the failure and retries after the next cache window, so a rate-limited RPC no longer turns `/series` into a 500 or hammers the RPC on every request. Safe for every cached read: series never change, the contract config has no setter the relay uses, and a stale fee or salt makes a trade fail its simulation, never execute wrongly. A slow, retrying RPC still delays requests until near-api-js gives up.
- **Lite wears the NEAR look too; Pro and Positions keep Horizon.** The default screen should look like it belongs to NEAR, like Tap ("NEAR future" canvas): NEAR's green, coral, teal and bone on near-black, Mona Sans (open, used on near.org; NEAR's own FK Grotesk is licensed) with mono labels, square hairline panels. It reuses Tap's token block on `<html>`, not a second component set, so Lite's components and the shared header and sheets stay single-sourced; shape and type changes in shared components (header, buttons, chips, popovers, sheets; 6 px radii, 14 px on sheets) go through a `near:` variant and radius tokens in that block, so Pro renders exactly as before. Per screen rather than app-wide, because Pro's chart is tuned for Horizon in both themes. Dark only, as the palette is built for it, so Lite and Tap hide the theme switch instead of showing one that does nothing there (supersedes "the theme switch still sets Lite and Pro" below). NEAR's logo stays off the app: the look says NEAR, the mark says near·options. The inline script in `index.html` sets the look before first paint, or light-theme users would see a grey flash on every load of the default screen.

## 2026-11-03

- **Tap wears a NEAR look; Lite and Pro keep Horizon.** It follows the "NEAR future" direction for the trade screen: near-black dot grid, NEAR green and coral, Mona Sans with mono labels, square panels. It is one token block on `<html>`, not a second theme or component set, so Tap's components and the shared header stay single-sourced. Dark only, as the palette is built for it; the theme switch still sets Lite and Pro.
- **Tap trades from a Tap balance signed in the browser.** A popup per tap kills the game, and an intents key has no spending limits, so a browser key must never sit on the main account. The Tap balance is its own implicit account whose ed25519 seed is the sha256 of one wallet signature over a fixed text: the same wherever the wallet signs with the same key, recoverable without storing anything, and worth at most what the user moved in. A stored random key would be lost with site data; a policy contract signing through chain signatures ([ideas/agent-trading.md](ideas/agent-trading.md)) is days of work. The seed lives in `sessionStorage`, not `localStorage`, so it doesn't outlive the tab.
- **Tap: a third trade mode, a grid of daily end dates by prices to beat.** Playful tap-to-buy like Euphoria's tap trading, in our own look, next to Lite and Pro (both unchanged). Columns are the listed 08:00 UTC end dates, not seconds: the price is a 30-minute average fixed by an oracle and final an hour later, and the contract can't be upgraded, so a cell resolves when its day ends. The fast feedback is the live price line, live value and selling back. Each cell is a real listed series: Up above spot, Down at or below it, never the other side swapped in, so a cell always means "ends above/below this row's price". It shows only the gross N×, the same ratio as Lite's chip. With a Tap balance a tap buys without a sheet, so the price the user accepted is the N× they tapped: it signs only if the firm quote still pays at least that, rounded the same way, and costs at most the stake + 5%, the "Max loss" printed under the stake. A 0.5% cap on the cost failed most taps on far cells, whose price moves several percent between two 5 s mark polls. Selling back keeps the confirm sheet: no multiple to promise there, and a sell is rare enough to read.
- **The relay sends USDC transfers for a $0.01 USDC fee instead of NEAR gas, and settled trades don't count against the quote limit.** The Tap balance is a separate intents account (an implicit account whose key the app derives), so filling and emptying it needs a move without NEAR, which EVM users don't hold. A free relayed transfer would be a gas faucet: implicit accounts cost nothing, so the same dollar can hop between fresh accounts forever, and a session from the receiver proves nothing about who owns it. So `POST /transfer` takes one plain USDC transfer (no `msg`, so intents calls nothing on the receiver) plus $0.01 to the relayer in the same signed payload: more than the gas, paid by whoever moves the money. Quick taps settle one trade every few seconds and would hit 4 quotes per 25 s within a burst, so a quote that settles gives its slot back within the window (it can never bank more than the window's 4); unpublished quotes stay at 4. A settled quote still holds its MM reservation to its deadline, so fast traders lock more inventory, but each lock is a real fill paying the spread.

## 2026-11-02

- **The trade screen defaults to Lite for every user.** People close options tickets within seconds; the sentence makes the bet readable first. Lite is one sentence (end date/time → asset → above/below → price to beat + % move → budget → win up to the capped gross payout) with a list behind each slot and no chart. A header Lite/Pro toggle, kept in `localStorage`, opens the existing chart ticket unchanged. Positions and the confirm sheet (`QuoteSheet`) stay shared. Chance is the estimated odds of ending past the price to beat, never of hitting the cap. "Win up to" is only that capped gross payout, not profit and not a guarantee; both views still show the honest cap scenario.

## 2026-11-01

- **The MM prices a bet at the worst of four vol scenarios and charges each fill the hedge trade it causes.** Before, each leg's vol moved 2 points against the user (the spread on gross vega) and every fill paid a hedge round trip. The MM hedges delta only and keeps the vol risk: a parallel move of both legs' vols (±2 points) and a skew move, each leg 1 point the opposite way (`SKEW_SHOCK` 0.5, a judgment call: the legs are ~2.5 % apart in strike, so their vols move apart much less than together). Pricing only the parallel move left bets with spot between strike and cap, whose legs' vegas cancel, almost free; the skew move prices ~$87 a contract on a centred bet a week out, where the old gross charge took ~$173. Hedge: each fill pays the trade it causes (|delta| × forward × fee), and a buy also pays closing it, since most bets are held to expiry. Anyone can write pairs and sell the long to the MM, so a buy-back can open a hedge too. Known gap: `MAX_VEGA_USD` caps net vega only, so skew exposure across many centred series is bounded only by the per-series cap.

## 2026-10-29

- **The MM's delta cap defaults to $50,000, not $2,000.** The cap applies to the delta right after a fill, before the hedger runs, and a capped bet carries a lot of delta per dollar: one $25 out-of-the-money BTC bet a day out is ~$3.5k, so at $2,000 the testnet MM refused every near-money bet as `over delta cap`. Near expiry a capped spread's delta approaches one per contract, so a full `MAX_TRADE_USD` trade there is up to `MAX_TRADE_USD × spot / width` (~$80k for BTC, more for ETH); at $50k those are refused, while $100 bets 4 h out (~$25–40k) fill. The cap still bounds what's left unhedged if Hyperliquid fails. It is also each hedge order's size limit, so one IOC can now be up to $50k.
- **The ticket shows the market maker's own price (`GET /marks`) instead of a DVOL estimate.** DVOL is a 30-day vol and our bets last 4 h to 4 days. Over the 30 days to 2026-10-28 the app's ask on out-of-the-money bets was a median 28–58 % above the MM's ask (p90 +97 … +239 %), its chance % a median 2.4–5.5 points off (max ~21), and its cone 1.35–2× too wide. On the 2026-10-28 FOMC day it flipped: next-day BTC IV sat 4 points above DVOL and the app's ask was a median 10 % under the MM's, a tenth of bets over 38 % under, so the budget sizing bought more or less than the user meant. The MM now publishes, per series, the per-contract ask and bid its quotes use (one shared function, so a firm premium is `size × ask` before the $1 minimum) and its vol at the strike; the relay serves the best across MMs, kept 10 s, and the app polls it every 5 s. The relay and MM now set what the ticket shows; the pre-sign card still shows the exact `token_diff` ([security.md](security.md#threat-model)). A per-expiry ATM IV would have halved the event-day gap only; the smile, hedge cost and spread remained. Venues and the fallback: [ideas/pricing-sources.md](ideas/pricing-sources.md); raw numbers: `.research/pricing-sources.md`.

## 2026-10-28

- **The app verifies 1Click deposit quotes itself, with noble's pure-JS Ed25519 and SHA-256 in the SDK.** A compromised relay could otherwise swap the deposit address the app shows. WebCrypto Ed25519 would refuse every quote in older wallet in-app browsers and on plain-http dev hosts, so the SDK takes `@noble/curves` and `@noble/hashes` (the libraries 1Click's own SDK uses). Every signed request field comes from what the app sent, never from 1Click's echo.
- **The app refuses a deposit quote that loses more than 3% between its signed USD amounts.** 1Click doesn't sign `appFees`, so a compromised relay could take a cut that still verifies. Measured routes for every offered token lose at most 0.5% (stablecoins about 0.06%, BTC/ETH/SOL 0.3–0.5%, with no fixed fees; amounts too small for a bridge are refused by 1Click itself), so 3% blocks a meaningful skim without refusing real deposits. The sheet also shows the signed amount that arrives.
- **The oracle fails closed without Deribit on 08:00 expiries and needs two agreeing USDT/USD rates.** Before, a missing Deribit price let the median through unchecked, so blocking or rate-limiting Deribit removed the only independent check, and two tampered pairs (one USDT rate, one venue) could move the median ~48 bps, under both the 50 bp veto and the monitor. Now no Deribit means no price (the settler retries every 10 min for 6 h, then the manual path), and the USDT rate needs Coinbase and Kraken within 20 bps. A slower settlement on a Deribit outage is the price of never skipping the check.
- **Contract hardening before mainnet, from the security review of `59f11dd`.** The contract can't be upgraded, so these land before any mainnet deploy:
  - Our own `*_transfer_call` into `intents.near` takes only an empty or account-id `msg`. Today's intents never returns a promise from `mt_on_transfer`, but intents can be upgraded and we can't; a returned promise forced to fail would make our resolve refund tokens intents already credited (the Oct 2026 exploit's shape).
  - `withdraw_claimable(owner_id, asset)` is open to anyone and always pays `owner_id`, so an EVM user's failed payout isn't stuck. `payout_failed` events tell ops what to retry.
  - `create_series` creates, empty, the supply and intents balance rows its first write fills, so the creator pays for them; writes arrive from intents with no deposit.
  - When intents answers a deposit with something we can't read, `mt_resolve_transfer` refunds nothing; only an explicit failure refunds. If intents ever returns a promise for plain deposits, a forced failure would still refund here and in `on_options_delivered` (which moves delivered options back on any failure), and that needs a new deployment.
  - `propose_settlement` takes 1 yocto like every other privileged method; `request_settlement` refuses less than 300 TGas, so a request built to fail at OutLayer can't hold the lock and push an expiry to the manual path.
- **Only the lister's width is quotable.** `create_series` takes any width, so anyone can list a known strike again at another width. The relay marks only `listedWidth` (2 steps of the strike's own price grid, in the SDK) quotable, the MM quotes nothing else, and the app shows only quotable series, so a strike shows once. Other widths stay writable, collectable and transferable. Changing the rule later leaves old widths without quotes, so sell-back on them stops while collect keeps working.
- **The lister stocks the app's default end date first** (the first at least 6 h out, `defaultExpiry` in the SDK), then the rest nearest first. With a partial budget the ticket people see first has inventory, except when the default moves to the next day before today's unsold stock is burned at its write cutoff: about 02:00–07:30 UTC with ~$6k. Burning today's stock early to fund tomorrow would empty today's market instead; a full budget (~$40k) removes the gap.

## 2026-10-27

- **Open series are read from an index keyed by `(expiry, series_id)`, paged by cursor.** `list_series_by_expiry(from_expiry, after_id, limit)` is a range read on a `near_sdk::store::TreeMap` (needs near-sdk's `unstable` feature, which only unlocks extra APIs; the stable `legacy` TreeMap re-walks from the root per item), so a page costs the same however many series have expired. Entries never leave: expired ones sit below the range start, and deleting them would add writes to settle and redeem. A cursor, because an offset still reads every skipped entry. ~160 bytes (~0.0016 NEAR) more per series, paid by the `create_series` caller. Readers ask only for what they use: MM bot from now, proposer from now − 1 day, settler from now − oracle window, lister and relay from now − 7 days (`CLAIM_WINDOW_SEC`, so gasless collect ends there too). The monitor and `positions` keep `list_series`: they need every expired series.
- **The mainnet settler signs `request_settlement` with the relayer's account and key, retrying every 10 min.** The relayer is already our hot gas payer, the mainnet plan creates it with a full-access key (a function-call key can't attach the 0.01 NEAR), the monitor already alerts on its NEAR, and OutLayer refunds the unused deposit to it. Sharing the key with the relay is safe: near-api-js re-signs on a nonce clash, and the settler sends a few transactions an hour at most. The owner's key never goes in a bot, and mainnet's oracle account defaults to the owner. 10 min matches the contract's stale-lock timeout and leaves OutLayer's 2 min yield plenty of time to answer: at most 36 tries per expiry inside the 6 h window. It refuses a non-mainnet RPC: the proposer settles testnet.
- **The relay verifies 1Click's quote signature against a pinned key, over the request it sent.** The browser shows `depositAddress` to send funds to, so a tampered quote steals the deposit. 1Click documents the signed message but not a key endpoint; the key is the one its SDK pins, and the SDK's `verifyQuoteSignature` is mirrored rather than added as a dependency (it would pull in its own hash, base58 and Ed25519 libraries next to `near-api-js`). Hashing our own request fields instead of 1Click's echo also rejects a genuine quote for another recipient, asset or amount. A key rotation makes every deposit quote `502` until the constant changes. (Superseded 2026-10-28: the check lives in the SDK and the app runs it too.)
- **Every series is capped and collateralized in USDC.** Up pays `S−K`, Down pays `K−S`, each at most `width`, and every write locks `width` per contract in USDC. An uncapped Up locked a whole BTC to sell a ~$25 bet, about $150 locked per $1 of premium. Capped at 2 strike steps (~1.2–3% of the strike) it is about $5. Each market is stocked with $500 of max payout: $25–$50 bets fit near the money down to the last hours, $100 bets a day or more out; very cheap far strikes near the end hit the MM's $2,000 max-payout trade cap. Fully stocking the 80 listed markets takes ~$40k of USDC (uncapped, the same depth took ~$500k of BTC, ETH and USDC); with ~$6k the lister stocks ~11 markets, the default end date first. One collateral asset also means one math path and USDC-only payouts. The width is a series parameter, so the lister picks it and the contract stays generic. Ids become `BTC-27NOV26-110000_112000-C` (strike, then cap). Supersedes the 2026-10-23 entries on Deribit-name ids, call collateral and token decimals.

## 2026-10-26

- **Oracle changes wait `oracle_delay_sec` (fixed at deploy, 1 day on mainnet); ownership moves in two steps.** A new oracle account or WASM can't price anything for a day, and `get_pending_oracle_changes` shows it coming. Removing an oracle stays instant: it only takes power away. `propose_owner` + `accept_owner` let the owner move to a multisig or DAO without a typo risk. Testnet uses 60 s. This doesn't yet protect against a captured owner: `override_settlement` sets any price inside the dispute window with no delay ([known gaps](security.md#known-gaps-accepted-for-the-hackathon-tracked)).

- **1Click deposit quotes go through the relay with our partner JWT (`POST /deposit-quote`).** Unauthenticated quotes add 25 bps to every deposit; with the key it's 20 bps, 1 bp on stablecoin routes (USDC/USDT → USDC). The JWT can't ship in the browser. The relay forwards only deposits into an intents balance in our quote asset with no `appFees`, `rebates` or `referral`, so nobody can take fees under our key. Anyone can still use it as an on-ramp into intents USDC ([known gap](security.md#known-gaps-accepted-for-the-hackathon-tracked)).

## 2026-10-25

- **Testnet faucet in the relay: 100 mock USDC per account and per IP a day, 200 a day in total.** Judges and testers on the hosted app had no way to fund an account. The relayer already owns the mock USDC supply and signs transactions, so the faucet is one route, not a new service. Mainnet refuses to start with it. Every attempt counts toward the 200, and only an explicit token refund frees the account and IP: a failing faucet can't burn relayer gas, and a timeout can't pay twice.

- **Settle on the median of 7 exchanges' 30-min TWAPs, not Deribit's delivery price. Deribit is only a veto.** At 08:00 UTC expiries, if its delivery price is more than 50 bps from the median, there's no price and manual settlement applies. Deribit alone never settles.
  - One venue's outage, API change or bad print shouldn't decide every payout. The median needs any 3 of 7.
  - "Median of 7 major exchanges" is a claim users can check without trusting one company.
  - Deribit's index is itself a composite of these same venues, so the number barely moves (0.1 bp apart on 2026-10-23).
  - The veto keeps a second opinion that catches a broken median before it's proposed. The monitor checks every proposal against Deribit too.

## 2026-10-24

- **Quotes need a signed session and a balance that covers the signer's open quotes.** Free unsigned quotes let anyone keep MM inventory reserved, and per-signer caps on an unauthenticated `signer_id` let an attacker lock out the victim they name. One empty-intents signature per day costs the user nothing and the verifier checks it for us.
- **Timing (expiry grid, write cutoff, oracle window, horizon) is fixed at deploy.** Mainnet uses the Deribit daily grid. The testnet demo uses minute expiries, so a full expiry, settlement and payout cycle fits on stage. No setter exists, so the owner can't move the goalposts on live series.
- **Own testnet intents deployment** from the exact mainnet wasm, because there's no official intents testnet.

## 2026-10-23

- **Seven venues in the settlement cross-check: Coinbase, Kraken, Bitstamp, Bitfinex (USD) and Binance, OKX, Bybit (USDT converted via a USDT/USD TWAP).** Median of at least 3. The biggest venues by volume are USDT-quoted, so they need the conversion. Measured 0.1 bp from Deribit on 2026-10-23. Only free public APIs, no keys.
- **Sandbox tests run against the exact mainnet `intents.near` wasm** (pulled via RPC `view_code`), because there is no intents testnet. Users call `intents.near::mt_batch_transfer_call` directly: same `mt_on_transfer` path as a signed `transfer` intent, no signing needed. Time travel to expiry is too slow in the sandbox, so exercise is unit-tested only.
- **Oracle WASM shares the crate between native tests and wasip2.** `wasi-http-client` compiles on native, so the same code runs in tests with recorded API responses and live in wasmtime/OutLayer.
- **Callbacks act only on an explicit failure.** A successful call with an unreadable result counts as success. Treating it as failure would hand out a second copy (fresh-context review, high finding).
- **Ledger transfers pay for new storage, except transfers coming from `intents.near`.** This stops balance-row spam from draining the contract while keeping withdrawals out of intents working.
- **Writes close 30 min before expiry on mainnet** (now `timing.write_cutoff_sec`). That is when the 30-min TWAP window opens and the price becomes partly known. The MM stops quoting at the same time.
- **Retired option tokens stay in our intents account, no burn round-trip.** Burning would need an async `mt_withdraw` back to our ledger, which adds a failure mode for no gain. Nothing can move them out. The ledger stays consistent with intents.
- **Settlement is final by time (`final_at`), no `finalize` tx.** One less transaction and one less thing to forget. The owner can override inside the window.
- **Oracle: OutLayer TEE running our pinned WASM, Deribit delivery price with a CEX TWAP cross-check** (price source superseded 2026-10-25). Pyth left NEAR, `priceoracle.near` is dead, and nothing else offers a fixing at a past timestamp. The interim fallback is a whitelisted oracle account.
- **Collateral and options live inside `intents.near`. Users reach us only via a signed `transfer` intent with `msg`.**
  - Intents refunds the signer cleanly if we panic.
  - No storage registration on token contracts.
  - Payouts are pure ledger moves.
  - `ft_withdraw`/`mt_withdraw` with `msg` don't refund on failure, so we don't use them.
- **Receivers return plain values. All follow-up calls are detached.** The Oct 2026 Intents exploit came from a returned promise an attacker could force to fail.
- **Own RFQ relay: HTTP for users, WebSocket for MMs.** The official bus needs a partner JWT and KYC, and doesn't list NEP-245 assets.
- **Token ids follow Deribit instrument names** (superseded 2026-10-27). Long = `BTC-27NOV26-110000-C`, short = `…-SHORT`. The MM maps them 1:1 to Deribit for pricing, and wallets show something readable. Ids are derived by the contract from typed fields.
- **Expiries only at 08:00 UTC on mainnet.** That is Deribit's daily expiry: the MM prices from the same Deribit expiries, and the oracle can veto against Deribit's delivery price, published only then. (Testnet minute expiries: see the 2026-10-24 timing entry.)
- **European, cash-settled, fully collateralized.** Calls in the underlying, puts in native USDC (calls superseded 2026-10-27). No margin engine, no liquidations, no MM default risk.
- **Option token decimals equal underlying decimals** (superseded 2026-10-27: now just the `decimals` set per underlying). Calls lock exactly `amount` of underlying with no conversion rounding.
- **Math in u128 with U256 intermediates. Rust and TS share `testdata/vectors.json`.**
- **No upgrade path in the contract for the hackathon.** Fixes ship as a new deployment, and old series stay redeemable.
